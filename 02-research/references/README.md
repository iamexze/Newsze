# References

[`../competitors.md`](../competitors.md).

## Naming
`YYYY-MM-DD-<product>-<screen>.png` — e.g. `2026-11-12-sensibull-option-chain.png`.
Date matters: these are a record of what a competitor looked like at a point in time, which
is exactly what makes them useful 18 months later.

## What's worth capturing
| Capture | Because |
|---|---|
| How competitors present **uncertainty** (usually: not at all) | Our cone/band design is a differentiator — document the absence |
| How they present **sources and provenance** | Our provenance promise is a differentiator |
| How they handle **empty / thin-data states** | Ours is a trust feature; theirs are usually afterthoughts |
| Their **pre-open / morning** surfaces | Direct competition for loop L1 |
| **Option chain and OI** presentation | The densest screen we have to design |
| **Paywall moments and pricing pages** | Phase 6 conversion design |
| **Onboarding flows** | Our target is <120s to first value |

## Non-competitor inspiration worth collecting
Election forecasts (fan charts, calibration, public accountability) · weather forecasting
(probability communication to a general audience) · sports analytics (win probability as a
live number people trust) · forecasting-tournament scoreboards (how to display a track
record honestly) · aviation incident reporting (how to publish your own failures and gain
trust by doing it).

> That last one is the real reference class for the Accuracy Ledger.
